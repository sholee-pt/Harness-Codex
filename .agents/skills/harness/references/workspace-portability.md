# Portable workspaces and host capabilities

- Resolve project files from the current selected root. Manifest evidence and managed paths remain project-relative; keep that rule in generated procedures and command examples too. A Git repository, shared mount or server name does not change the selected ownership boundary.
- Treat absolute paths in old conversation history or a user brief as references, not permanent execution bindings. Locate the corresponding current file before use. `harness-codex context --project CURRENT_ROOT --resolve OLD_PATH` translates recorded project-root prefixes only. For older installations without a recorded prefix, the user can register one with `--remember-root OLD_ROOT`; do not guess an unrelated external path or rewrite the user's source/configuration automatically.
- Configuration records `.harness/context.json` separately from the manifest. It holds bounded root history and host-specific sandbox observations, never commands, credentials, permission grants or task state. Do not edit this CLI-owned file or add it to managedFiles/evidence. After switching hosts or mount paths, read `harness-codex context --project CURRENT_ROOT` once, not per turn. If it is not tested, use `--refresh` once when shell capability matters. A copied project does not inherit another host's sandbox verdict.
- The Linux probe executes a harmless command through the current Codex sandbox with a timeout. Missing PATH `bwrap` alone is inconclusive because Codex can use a bundled helper. `available` only establishes that this probe worked; it does not prove all operations or the active conversation's permission profile work. `unknown` is not permission to bypass restrictions.
- On a recorded/observed sandbox setup failure, avoid repeating the identical failed command. Pass the host limitation to native delegates; use a native approval route only if allowed by the user and effective policy, or report the host repair requirement. Never disable sandboxing automatically. Refresh after repair. Diagnostics expire and are rechecked on later launches or configuration, not on every prompt.
- Keep Graft centered on the selected project. If a task explicitly needs external code and the user has authorized reading that source, attach only that file or narrow directory with `harness-codex graft add PATH --name LABEL --project CURRENT_ROOT`. No automatic ancestor/home crawl. `graft status` lists bindings; `graft remove LABEL` detaches one. External resources remain host-local selections; reselect them on a different server.
- External retrieval uses a project-specific structural side index. It does not prove cross-root dependency edges or make external files project-owned. Verify the original source paths before edits. On missing/bounded/failed retrieval, retain ordinary source reads and the primary project results. External snippets are excluded from Jev advice; no summarization or model call is added by indexing.
