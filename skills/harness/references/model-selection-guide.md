# Claude 모델 선택 가이드

모델 카탈로그와 도구 가용성은 Claude Code 버전, 계정, 설정에 따라 바뀐다. 하네스는 특정 시점의 모델 이름을 영구 정책으로 고정하지 않는다.

## 기본 원칙

1. 현재 세션에서 선택 가능한 모델과 상속 규칙을 먼저 확인한다.
2. 명시적 오버라이드가 필요하지 않으면 부모 세션의 모델을 상속한다.
3. 오버라이드가 필요하면 복잡도, 작업 기간, 자율성, 응답 속도, 비용을 근거로 선택한다.
4. 모델 이름과 선택 근거를 함께 기록한다.
5. 요청한 모델이 없거나 필요한 도구를 제공하지 않으면 지원되는 모델로 되돌리고 그 사실을 보고한다.

## 업무별 판단

현재 제공되는 모델 중에서 다음 기준을 적용한다.

| 업무 성격 | 우선 기준 |
|---|---|
| 설계, 교차 검증, 방법론 비판, 장기 계획 | 높은 추론 품질과 자율 실행 능력 |
| 명확한 수집, 포맷 변환, 정적 검사 | 속도와 비용 효율 |
| 대량 병렬 작업 | 개별 워커 비용, 동시성, 결과 통합 비용 |
| 보안·릴리스 판단 | 필요한 도구 가용성과 높은 검증 품질 |

모델의 마케팅 등급이 아니라 실제 역할의 실패 비용으로 선택한다. 계획·조율 계층이 고성능 모델을 사용하더라도 모든 워커에 같은 모델을 강제할 이유는 없다.

## 검증

- 에이전트별 모델 오버라이드가 실제로 지원되는지 현재 공식 문서에서 확인한다.
- 모델을 바꾸면 대표 작업으로 결과 품질과 비용을 다시 비교한다.
- 문서에 없는 모델명, 별칭, 도구 지원을 추론하지 않는다.
